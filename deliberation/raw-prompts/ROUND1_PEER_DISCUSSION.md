## 二、前期沉淀的核心洞见与问答（请审阅并挑战）

### 1. 关于 Addy Osmani 原文的核心提炼
- **认知滑坡光谱**：从 `Cognitive Offloading`（认知卸载：委托执行但掌握假设与因果） $\rightarrow$ `Deferral`（认知顺从：把 AI 输出直接当下一步的默认真理） $\rightarrow$ `Cognitive Surrender`（认知投降：测试全绿直接合并，线上出问题时连某行代码的因果都解释不清，积累严重的 **理解债务 Comprehension Debt** 与 **意图债务 Intent Debt**）。
- **三大反直觉**：
  1. **绿灯测试是最危险的盲区诱饵**：Agent 写测试极便宜，但若测试带着与实现代码相同的认知盲区编写，测试依然全绿。当检查变绿时，不仅要问它证明了什么，更要问**“它漏测了什么（What did it NOT check?）”**。
  2. **代码评审的核心不是看 Diff 格式，而是逼出 Agent 擅自做的“微决策”**：长会话中 Agent 默默做了大量折中（翻转默认值、忽略并发竞争、重解释冲突需求），Summary 只报喜不报忧。
  3. **监督悖论（Paradox of Supervision）**：有效监督 Agent 所需的工程直觉，恰恰因过度依赖 Agent 而退化；执行与初筛可外包，但**可归责性（Accountability）永远不可外包**。

### 2. 用户追问与 Antigravity 的深度推演

#### 追问 ①：追问“漏测了什么”是否会导向另一个极端——过度优化与防御性编程？如何让测试不包含相同的认知偏差？用 Codex 和 Claude 分别做代码和测试可行吗？
- **防过度防御的边界**：
  - **错误的防御（过度设计）**：为假想极端情况在业务代码内部加一堆兜底分支、冗余参数校验（违背 `AGENTS.md` 中“只在真实边界做错误处理，内部调用相信调用方”）。
  - **正确的漏测追问（不变量与变异思维 Mutation Thinking）**：不是在业务代码里堆砌防御分支，而是针对**真实契约边界与核心业务不变量（Invariants）**做反证思考——*“如果我故意把某行核心逻辑写反（如事务顺序颠倒、状态判断取反），现有测试会变红报错吗？”* 如果依然全绿，说明是形式主义假测试。
- **双模型交叉（Codex 写实现 vs Claude 写测试，或反之）**：
  - **优势**：强力打破单一模型在同一上下文窗口内的“自圆其说 / 语义共谋（Self-confirmation bias）”。
  - **盲区警告**：若人类上游给出的需求/契约（Spec）本身模糊（存在 Intent Debt），由于主流大模型预训练分布相似，两个模型极可能在同一个模糊点做出相同的“常识性错误假设”。因此必须配合**“前置明确契约 + 上下文隔离（写测试的一方只看契约与接口，不看实现过程）”**。

#### 追问 ②：强制 AI 说明重构/编码过程中的“隐含假设和架构折中”
- 用户高度认可这一动作。因为 LLM “不问不说、一问全知”，强制其在动手前或交付时自曝“擅自做出的前 3 个隐含假设、忽略的边缘情况、最脆弱单点”，能以极低成本把隐性意图债务显性化。

#### 追问 ③：监督悖论只能靠人更多介入吗？大模型不同于当年的汇编编译器抽象，解法是什么？
- **为什么不能类比汇编编译器**：编译器是数学确定性、语义严格等价的转换；大模型是概率近似匹配，存在幻觉与意图漂移。放弃理解底层原理会导致：**系统大冻结（没人敢改的屎山）**、**安全与资金漏洞**、**虚假业务闭环**。
- **分层介入解法**：不是让人每行代码都低效肉身介入，而是**按失败成本分层治理**：
  - **高风险/核心资产**（资金、安全、核心状态机、架构边界）：人类必须掌握因果图并亲自签名；
  - **中风险/常规业务流**：靠机制化门禁（隐含假设自曝、变异反问、双模型交叉审查、Quiz 考题准入），人看客观证据而非 Summary；
  - **低风险/机械样板**：100% 认知卸载，错也便宜。
